## 1. Custom Hooks

A **Custom Hook** is an architectural pattern that allows you to extract component logic into reusable, pure JavaScript functions.

### ⚙️ Engine Mechanics: State Isolation

The most important rule to memorize is: **Custom Hooks do not share state.** Every time a component calls a custom hook, it creates an entirely isolated state bucket and effect lifecycle inside React's internal Fiber node for *that specific component instance*. It is a mechanism for sharing *stateful logic layout*, not shared global state data.

### 🛠️ Production Code: High-Performance Network/State Sync

A common production requirement is tracking network connectivity status. Here is an optimized custom hook that cleanly abstracts DOM event synchronization:

```jsx
import { useState, useEffect, useDebugValue } from 'react';

export function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const handleOnline = () => setIsOnline(true);
    const handleOffline = () => setIsOnline(false);

    // Synchronize with Browser Web APIs
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);

    // Cleanup phase to prevent memory leaks in the DOM
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  // Displays a custom label inside React DevTools for easier debugging
  useDebugValue(isOnline ? 'Online Now' : 'Offline Status');

  return isOnline;
}

```

## 2. Error Boundaries

An **Error Boundary** is a specialized React component that acts like a `try/catch` block for your visual user interface layout. It intercepts unhandled JavaScript exceptions thrown *during* the rendering phase, inside lifecycle methods, or inside hooks of its child component sub-tree.

### ⚠️ The Execution Constraints

Error Boundaries **cannot** catch errors that occur inside:

1. Asynchronous event handlers (e.g., a `fetch` failure inside an `onClick` callback—you must use standard `try/catch` there).
2. Asynchronous timers (`setTimeout`).
3. Server-Side Rendering (SSR) environments.

### 🛠️ Production Code: Class-Based Resilient Layer

As of modern React specifications, Error Boundaries **must be written as Class Components** because functional components do not yet support the underlying lifecycle hooks required to catch rendering panics.

```jsx
import React, { Component } from 'react';

export class GlobalErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, errorLog: null };
  }

  // Lifecycle Rule 1: Catches the error and updates state to render a fallback UI
  static getDerivedStateFromError(error) {
    return { hasError: true };
  }

  // Lifecycle Rule 2: Used for logging the error details to external analytics telemetry
  componentDidCatch(error, errorInfo) {
    console.error("ErrorBoundary intercepted an application panic:", error, errorInfo);
    // this.logToService(error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      // Elegant, resilient fallback layout instead of crashing the entire browser tab
      return (
        <div className="error-fallback-card">
          <h3>Something went wrong down the line.</h3>
          <button onClick={() => this.setState({ hasError: false })}>Try Again</button>
        </div>
      );
    }

    return this.props.children;
  }
}

```

## 3. Portals

A **Portal** allows you to render a child component node into a completely different destination physical DOM node located entirely outside the parent HTML DOM tree structure, while maintaining standard React architectural event behaviors.

### 🧠 The Event Bubbling Paradox

Even though a Portal node is physically mounted somewhere else in the HTML DOM (e.g., directly under `<body >`), **it behaves exactly like a normal React child node in terms of Event Bubbling and Context.** An event fired inside a Portal will still bubble up through its original conceptual location in the React Virtual DOM tree hierarchy, ensuring your global event capturing systems don't break.

### 🛠️ Production Code: Accessible Overlay/Modal Architecture

```jsx
import { useEffect, useMemo } from 'react';
import { createPortal } from 'react-dom';

export function OverlayModal({ isOpen, children, onClose }) {
  // Create a persistent container element in memory
  const modalContainer = useMemo(() => document.createElement('div'), []);

  useEffect(() => {
    const modalRoot = document.getElementById('modal-root') || document.body;
    modalRoot.appendChild(modalContainer);

    return () => {
      modalRoot.removeChild(modalContainer);
    };
  }, [modalContainer]);

  if (!isOpen) return null;

  // Teleport the React Virtual DOM nodes straight into the modalContainer target
  return createPortal(
    <div className="modal-backdrop" onClick={onClose}>
      <div className="modal-content-surface" onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    modalContainer
  );
}

```

## 4. Concurrent Features

Before modern concurrent execution modes, React rendered updates using a **blocking, synchronous process**. Once a large tree render started, the main thread was completely locked up until it finished. If a user tried to type while a heavy list rendered, the page stuttered.

**Concurrency** transforms rendering into an **interruptible process**. React can now pause a low-priority background render to handle a high-priority user interaction (like a keystroke or mouse click), and then resume the background work seamlessly.

### Core Primitives: `useTransition` & `useDeferredValue`

* **`useTransition`:** Lets you mark a state-setting operation as a low-priority "Transition." High-priority operations (like text inputs) can interrupt it.
* **`useDeferredValue`:** Lets you defer updating a specific value snapshot (like a search term passed down to a heavy data grid) so the UI remains fluid.

### 🛠️ Production Code: High-Performance Search Splitting

```jsx
import { useState, useTransition, useDeferredValue } from 'react';

export function ConcurrentDataGrid({ largeList }) {
  const [searchTerm, setSearchTerm] = useState("");
  const [isPending, startTransition] = useTransition();
  
  // Create a lower-priority, deferred version of the search value
  const deferredSearchTerm = useDeferredValue(searchTerm);

  const handleSearchChange = (e) => {
    // High Priority: Update input box layout immediately
    setSearchTerm(e.target.value);
  };

  const filteredList = largeList.filter(item => 
    item.text.toLowerCase().includes(deferredSearchTerm.toLowerCase())
  );

  return (
    <div className="grid-container">
      <input type="text" value={searchTerm} onChange={handleSearchChange} placeholder="Search names..." />
      
      {/* Visual cue showing that a low-priority background thread render is processing */}
      {isPending && <div className="spinner">Recalculating layout...</div>}

      <div className="data-rows">
        {filteredList.map(item => <div key={item.id}>{item.text}</div>)}
      </div>
    </div>
  );
}

```

## 5. React Server Components (RSC)

**React Server Components (RSC)** represent a paradigm shift where components are executed directly **on the server** and compiled into a lightweight, streaming data format before being sent to the browser client.

### ❌ The Common Misconception: RSC is NOT SSR

* **Server-Side Rendering (SSR):** Generates flat HTML strings on the server. The browser downloads the HTML, downloads the entire JavaScript bundle, and runs a process called **Hydration** to attach event listeners. The entire component architecture still lives in the client bundle.
* **Server Components (RSC):** The actual component file code **never ships to the browser**. The server runs the component, talks to the database directly, strips out the dependencies, and generates a static layout description stream. This cuts down your final client-side JavaScript bundle footprint to nearly zero.

### The Two Component Worlds

#### Server Components (Default)

* Can be `async`.
* Can fetch data directly from databases (`fs.readFile`, SQL queries).
* ❌ Cannot use hooks (`useState`, `useEffect`).
* ❌ Cannot listen to browser events (`onClick`).

#### Client Components (Opt-in)

* Defined by placing the `"use client"` directive at the very top of the file.
* Can use hooks, context, and standard interactive browser APIs.

### 🛠️ Production Architectural Layout

#### `ProductDetailsServer.jsx` (Server Component - No Client Bundle Weight)

```javascript
// This component runs exclusively on the Node/Server infrastructure
import { db } from '@/infra/database';
import { InteractiveReviewButton } from './InteractiveReviewButton';

export async function ProductDetailsServer({ productId }) {
  // Query data directly without an intermediate internal fetch API layer
  const product = await db.query('SELECT * FROM products WHERE id = ?', [productId]);

  return (
    <section className="product-layout-card">
      <h1>{product.title}</h1>
      <p>{product.description}</p>
      <div className="price-tag">${product.price}</div>

      {/* Interactivity boundaries are safely offloaded to Client Component leaves */}
      <InteractiveReviewButton productId={productId} />
    </section>
  );
}

```

#### `InteractiveReviewButton.jsx` (Client Component Leaf)

```javascript
"use client"; // Injects this specific leaf down to the browser bundle frame

import { useState } from 'react';

export function InteractiveReviewButton({ productId }) {
  const [likes, setLikes] = useState(0);

  return (
    <button onClick={() => setLikes(prev => prev + 1)}>
       Like this Product ({likes})
    </button>
  );
}

```

| Advanced Concept | Where it Executes | Memory / Bundle Implication | Primary Use Case |
| --- | --- | --- | --- |
| **Custom Hooks** | Client Thread | Completely isolated memory states per component instance call. | Abstracting complex stateful logic routines. |
| **Error Boundary** | Client Layout | Catches run-time execution crashes inside the lifecycle tree. | Graceful UI recovery and centralized crash telemetry logging. |
| **Portals** | Client DOM Tree | Bypasses HTML cascading layouts while preserving virtual bubble rules. | Overlays, dropdown menus, modals, and absolute tooltips. |
| **Concurrent Features** | Client Work-Loop | Makes layout trees interruptible, prioritizing interaction frames. | Heavy filtering fields, slow components, and layout thrashing protection. |
| **Server Components** | Server Infrastructure | **Zero bundle footprint** shipped down to the user's browser. | Secure data fetching, low-latency rendering, and maximizing performance metrics. |
